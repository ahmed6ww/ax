ax · positioning & roadmap · aug 2026

The lockfile wedge

You cannot beat skills.sh at finding skills, and you should stop trying. Beat it at guaranteeing a team is running the same ones. Going vertical on Claude Code and Codex is what makes that possible — and it is the one thing a 76-agent tool structurally cannot copy.

The competitor, precisely

What Vercel actually shipped

Announced 20 January 2026 — seven months ago. Two pieces: a CLI (npx skills, open source at vercel-labs/skills, MIT) and a directory plus leaderboard at skills.sh.

Distributionnpx skills add owner/repo — zero install, npm-native. No binary to download.
Agent coverage76 agents — Claude Code, Codex, Cursor, Copilot, Windsurf, Gemini, Cline, and 69 more.
SourcesGit-native: GitHub shorthand, GitLab, any git URL, local paths, direct download URLs. There is no central package registry — skills.sh is a directory and leaderboard over git repos.
Install modelSymlink by default — one canonical copy, referenced from each agent. --copy when symlinks aren't available. Project or global scope.
Commandsadd · use · list · find · remove · update · init
VersioningNone. No semver, no version pinning. update fetches whatever is at the source HEAD.
LockfileA per-machine install ledger at ~/.agents/.skill-lock.json (schema v3), recording source, sourceUrl, skillPath, a skillFolderHash content fingerprint, and install/update timestamps. It carries no version, ref, tag or commit field — so it records what you happen to have, and cannot pin what you should get. It is user-global, not committed with a repo.
IntegrityThe folder hash detects local drift. No signature, no provenance, and nothing verified against the source — installing from arbitrary git URLs.
MCP serversNone. Not supported at all.
Team configNone. No project manifest, no dependency resolution.
TelemetryOn by default; opt out via DO_NOT_TRACK.

The field is more crowded than skills.sh alone. agentskill.sh ships ags with search, install, update and remove and claims a six-figure skill count. Anthropic ships plugins and marketplaces natively inside Claude Code. Three groups are already racing for the same catalog.

The honest part

The catalog race is over. You lost it.

Vercel has npm-scale distribution, a seven-month head start, 146 first-party skills, and a leaderboard that compounds. Do not build a directory. Do not build a leaderboard. Do not try to out-publish them.

But look carefully at that fact table. No version pinning. No project manifest. No MCP. Its lockfile is a per-machine ledger with a content fingerprint: it answers what do I have on this laptop, never what should this repository require. You cannot commit it, a teammate cannot reproduce from it, and with no ref recorded anywhere, skills update still pulls whatever is at the source's HEAD. Those are not oversights — they are the price of supporting 76 agents. A tool that must work everywhere can only install the lowest common denominator, and the lowest common denominator across 76 agents is a markdown file copied into a folder.

Every tool in this space today is optimized for one developer trying one skill once. Not one of them is built for a team that needs its agent environment to be identical across machines, reviewable in a pull request, and safe to run. That is an entire product category sitting empty, and it is empty for a structural reason your competitors cannot design their way out of.

Why vertical wins

Two targets buy you surfaces the others can't touch

Dropping Cursor is not a retreat. Cursor was the only target using a foreign format — .mdc rules. Claude Code and Codex both speak the same Agent Skills standard, so the “transpiler” framing dies and is replaced by something more valuable: ax stops translating files and starts provisioning environments.

Two things in that table matter more than the rest. First: ax already does MCP and skills.sh does not do it at all. That is a beachhead you own today and have never marketed. Second: Claude Code natively loads a skill folder containing .claude-plugin/plugin.json as a plugin that bundles agents, hooks and MCP servers together. There is a supported, first-party mechanism for shipping a whole environment as one unit — and it is only reachable if you are vertical enough to target it.

Before any of this: ax does not currently work on either target. Claude Code reads ~/.claude/skills/, but ax writes to the Claude Desktop directory on macOS and Windows. Codex reads ~/.agents/skills/ and .agents/skills/, but ax writes to ~/.codex/skills/, which Codex never scans. Installs report success and land where nothing reads them. Fixing the paths is item 0 and it gates the entire strategy — see PATH-01 and PATH-02 in the audit register.

Position

How to say it in one line

skills.sh helps you find a skill. ax makes sure your whole team is running the same ones.

Verified, pinned, reproducible — across Claude Code and Codex. If you prefer the analogy: skills.sh is curl | sh for agent skills; ax is package-lock.json for agent environments.

This ecosystem is seven months old. It is at precisely the stage npm was at before lockfiles — everyone installing from HEAD, nobody able to reproduce a build, and no one yet embarrassed by it. Someone is going to build the reproducibility layer. Being second to the catalog and first to reproducibility is a far better position than the reverse, because catalogs are winner-take-all and infrastructure is sticky.

The build

Six things, in this order

0

Make it actually workGates everything

Correct the install paths for both targets, add project scope, and write an integration test that asserts a file lands where the agent's own documentation says it looks. Until this ships, every other feature is theoretical. This is days of work, not weeks.

1

ax.toml + ax.lock + ax syncThe moat

Commit a manifest to the repo; every teammate runs one command and gets a byte-identical agent environment on both Claude Code and Codex. ax sync --check in CI fails the pull request when someone's setup has drifted.

# ax.toml — committed to the repo
[targets]
agents = ["claude-code", "codex"]
scope  = "project"

[skills]
"vercel-labs/agent-skills#nextjs"   = "1.4.0"      ← pinned
"ahmed6ww/ax-agents#rust-architect" = "^2.0"

[mcp]
context7 = { command = "npx", args = ["-y", "@upstash/context7-mcp"] }

[hooks]
pre-commit = "ahmed6ww/ax-agents#fmt-guard"

The lockfile beside it must record what the competitor's does not: a resolved commit SHA per skill, the digest of every file installed, and the target each one was rendered for — committed to the repo, not kept in $HOME.

Nobody has this. skills.sh's ledger is per-machine and records no ref, so it cannot express a requirement — only a history. The two things that make a lockfile reproducible are the two things it omits: a resolved commit per skill, and living in the repo. This is the single feature that turns ax from a preference into a requirement — the thing a staff engineer mandates for the team rather than a tool an individual happens to like.

2

Bundles — install an environment, not a file

One ax install provisions skills, subagents, slash commands, hooks, MCP servers and tool permissions together, as a versioned unit. Emit a Claude Code plugin via .claude-plugin/plugin.json so you are riding Anthropic's native distribution mechanism instead of competing with it.

This is the concrete payoff of going vertical: a competitor supporting 76 agents can never ship it, because 74 of those agents have no concept of a hook or a subagent.

3

ax audit — show what you're about to runDefensible

Every skill is a prompt-injection surface and every MCP server is command execution on the developer's machine. skills.sh installs from arbitrary git URLs with no verification of any kind. Print what a bundle will execute, which tools it grants, and what changed since the last install; verify digests; refuse on mismatch.

This turns the security work from the audit into the sales story. It is also the first question a security team asks, and right now nobody in this ecosystem has an answer.

4

Interoperate — don't fight the catalog

ax install vercel-labs/agent-skills must simply work, along with any git URL skills.sh accepts. Consume their ecosystem and wrap it in pinning, locking and verification.

This kills the “but they have a hundred thousand skills” objection outright. You are not the rival catalog; you are the safe, reproducible way to consume every catalog. It also means your addressable content library is theirs on day one.

5

Profiles — ax use frontend

Swap an entire agent environment per context: frontend work, infra, incident response, code review. Cheap to build once bundles exist, immediately demoable, and genuinely novel — nobody in the space has it. Good candidate for the launch demo precisely because it is the feature people can see working in ten seconds.

Risks

Two problems to face now, not later

Distribution — and a naming decision you can't defer

npx skills add x beats curl | sh plus a Rust binary for the thirty seconds where someone decides whether to try your tool. Keep Rust for the binary, but ship a thin npm wrapper that downloads the right prebuilt artifact so trial cost matches theirs.

That runs straight into a naming problem. ax is taken on npm, and ax on crates.io is an unrelated distributed-systems crate published in 2019 — which means the cargo install ax line currently in your README installs somebody else's package. ax-cli is also taken on npm; axcli and agentpm are free. Decide the published name now, while you have no users to migrate.

Anthropic may build this

Plugins and marketplaces are already native to Claude Code, and reproducibility is an obvious next step for them. You cannot prevent that. What you can do is stand where they structurally will not: Anthropic will never make Codex a first-class target. Cross-agent parity plus team reproducibility is a position that stays defensible even if Claude Code ships a lockfile tomorrow — and it is another argument for keeping Codex, not quietly deprioritizing it.

Consequences

What the pivot changes in the code

  • Delete cursor.rs — 181 lines, plus Target::Cursor, TargetArg::Cursor, cursor_config_dir() and the init detection. No findings disappear; several lose an evidence line.
  • ARC-06 collapses. The ~120 duplicated lines across the Claude and Codex installers become one shared skill renderer parameterized by root path, because both targets now emit the identical SKILL.md format. This was the hardest cleanup in the original plan and the pivot does most of it for free.
  • ARC-07 gets promoted. The capability model stops being tidy-up and becomes the core abstraction — Claude Code has skills, agents, commands, hooks, MCP and permissions; Codex has skills and MCP. Bundles are built directly on it.
  • BUG-12 gets a real answer. Codex has no subagent concept, so an agent's system prompt has to become a skill or an AGENTS.md contribution. Decide it explicitly instead of silently dropping the prompt on the floor.
  • P0 grows and P3 shrinks. Path correctness joins the containment phase. Cross-platform release polish matters less than being right on the two targets.

Revised phase order

P0  Correct paths · drop Cursor · the P0 security set     ~3 days

    ax uninstall · --json/--dry-run · CI

That is roughly six weeks to something genuinely differentiated, and the first three days of it are fixing a product that does not currently work on the platforms you are betting on.
